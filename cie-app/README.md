# vinext app

## Resume analysis

The User page sends a PDF resume (maximum 5 MB) and selected role to
`POST /api/analyze-resume`. It reads the role's skills and competencies from
D1 and calls OpenAI Responses with `gpt-4.1-mini`, strict Structured Outputs,
and `store: false`. Files are sent inline, so no OpenAI Files objects need
cleanup. Conskill does not persist resumes or results. OpenAI's own data
retention policies still apply.

For local use, copy `.dev.vars.example` to `.dev.vars` and replace the
placeholder with your OpenAI API key. Do not commit `.dev.vars`. Restart the
development server after setting it. For deployment, set the Worker secret
from this directory with `npx.cmd wrangler secret put OPENAI_API_KEY`.
Never put the key in client code. Without a key, the endpoint returns 503
with a configuration message.

The `RESUME_RATE_LIMITER` binding allows 3 requests per minute per client IP
per Cloudflare location. This is basic abuse protection, not a global spend
cap. Local requests share the `local` key. Unsupported Word files must be
exported to PDF for this MVP. Unreadable files and roles without skills
return actionable errors. At most 100 requirements can be analyzed at once.

The backend counts each competency once (or the skill itself when it has
no competencies), awarding 1 for demonstrated, 0.5 for partial, and 0 for
not demonstrated. Duplicate, missing, or unknown requirement IDs invalidate
the response. The percentage measures documented resume evidence, not
hiring eligibility. Results remain in page state and clear when inputs change.

Run `npm.cmd run test:ai` for deterministic scoring, upload validation, and
mocked-provider endpoint checks. These tests do not send resumes to OpenAI.

References: [OpenAI file inputs](https://developers.openai.com/api/docs/guides/file-inputs),
[Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs),
[Cloudflare rate limiting](https://developers.cloudflare.com/workers/runtime-apis/bindings/rate-limit/).

This project was created with create-vinext-app.

## Scripts

- `npm run dev` starts the vinext dev server.
- `npm run build` builds the Cloudflare Worker output.
- `npm run start` starts the built Worker locally with Wrangler.
- `npm run deploy` builds and deploys the Cloudflare Worker.

## Deploy to an existing Cloudflare Worker

Run commands from this directory. On Windows PowerShell, use `npm.cmd` and
`npx.cmd` if execution policy blocks the PowerShell wrappers.

1. Run `npx.cmd wrangler login` and complete the browser login.
2. Set `name` in `wrangler.jsonc` to the exact name of your existing Worker.
3. Run `npx.cmd wrangler d1 list` to find an existing database, or
   `npx.cmd wrangler d1 create cie-production` to create one for this app.
4. Update `d1_databases[0].database_name` and `database_id` in
   `wrangler.jsonc` with the real database name and UUID. Keep the binding
   named `DB`. The all-zero ID currently in the config is only a local
   development placeholder.
5. Run `npm.cmd run db:migrate:remote` to apply the schema to Cloudflare D1.
6. Run `npm.cmd run deploy`. The CLI prints the deployed Worker URL.

Deploying with the same Worker name updates that existing Worker. Use the
source `wrangler.jsonc` for configuration changes; `dist/server/wrangler.json`
is generated by the build. Local SQLite data is not copied to the remote
database by these migrations.

For a Cloudflare Workers Git build, set the root directory to `cie-app`,
the build command to `npm run build`, and the deploy command to
`npm run deploy -- --skip-build`.

## Local database

The app uses a Cloudflare D1 binding named `DB`. In local development, D1 is
backed by a SQLite file managed by Wrangler under `.wrangler/state`.

Apply the migrations before first use:

```sh
npm run db:migrate
```

Use the database in server-only code:

```ts
import { getDatabase } from "@/lib/db/database";

const roles = await getDatabase()
  .prepare("SELECT * FROM roles ORDER BY created_at DESC")
  .all();
```

Run an ad-hoc local query:

```sh
npm run db:query -- "SELECT * FROM roles"
```
